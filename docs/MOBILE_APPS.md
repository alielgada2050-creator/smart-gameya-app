# تطبيقات «جمعيتي» للجوال والتابلت والمتصفح

شيفرة واجهة واحدة (`apps/web`) تعمل في ثلاث صور:

| الصورة | لمن | كيف تصل للمستخدم |
|---|---|---|
| **المتصفح / تطبيق ويب قابل للتثبيت (PWA)** | الكمبيوتر وأي جوال أو تابلت | رابط الموقع؛ «ثبّت التطبيق» من المتصفح |
| **تطبيق أندرويد** (جوال وتابلت) | Google Play أو ملف APK | `apps/mobile/android` |
| **تطبيق iPhone و iPad** | App Store أو TestFlight | `apps/mobile/ios` |

التطبيقان الأصليان مبنيان بـ **Capacitor 8**: الواجهة محفوظة داخل التطبيق على الجهاز، وكل طلب يذهب إلى خادمك عبر HTTPS.

## ما الذي يختلف داخل التطبيقين
- **شريط الحالة** يتلوّن مع المظهر، وشاشة البداية بالكحلي، و**زر الرجوع في أندرويد** يغلق القوائم أولاً ثم يرجع بين الصفحات ثم يخرج.
- **مشاركة رابط الدعوة** بنافذة المشاركة في النظام (واتساب، رسائل…)، و**اهتزاز خفيف** عند التأكيدات المهمة.
- **الإيصالات** (0.14): ثلاثة أزرار في كل مكان يُرفق فيه إيصال أو سند: **صوّر الإيصال** (يفتح كاميرا الجوال مباشرة في أندرويد و iPhone/iPad؛ إذن `CAMERA` مضاف في أندرويد، ووصف استخدام الكاميرا والصور موجود في iOS)، **من الاستوديو**، **من الملفات** (PDF أو صورة). الصورة الكبيرة تُصغَّر إلى 2000 بكسل وتُحفظ JPEG قبل الرفع (أسرع، أقل من 5 ميجابايت، وتُحذف بيانات الموقع المخفية). على الكمبيوتر يفتح زر التصوير **كاميرا حية** داخل الصفحة، ويمكن **لصق** لقطة الشاشة أو **سحبها**. الصور تُفتح في عارض داخل التطبيق، وملفات PDF تُسلَّم لقارئ PDF عبر نافذة المشاركة.
- **الدخول بحساب Google داخل التطبيقين** (0.14): بنافذة Google الأصلية (Credential Manager في أندرويد، Google Sign-In في iOS) عبر الإضافة `@capgo/capacitor-social-login`. يلزم إعداد لمرة واحدة في Google Cloud (القسم التالي)؛ إلى أن يتم، تعرض شاشة الدخول في التطبيق تنبيهاً بالدخول من المتصفح.
- **الخطوط داخل التطبيق** (IBM Plex) فلا يحتاج اتصالاً بخوادم خطوط خارجية.
- **الخصوصية**: النسخ الاحتياطي السحابي ونقل البيانات بين الأجهزة معطّلان في أندرويد، فلا تخرج الجلسة أو الإيصالات من الجهاز. لا خرائط مصادر (source maps) داخل التطبيق.
- لا يوجد Service Worker داخل التطبيقين (الملفات أصلاً على الجهاز).

## الإعداد مرة واحدة
1. **عنوان الخادم**: التطبيق يبنى لخادم واحد عبر HTTPS. في GitHub: Settings ← Variables ← `API_ORIGIN` مثل `https://app.example.sa`. محلياً: `VITE_API_ORIGIN` في `apps/web/.env.native`. البناء يرفض عنواناً بلا HTTPS.
2. **على الخادم**: `CORS_ORIGINS=https://localhost,capacitor://localhost` (أصل تطبيق أندرويد ثم iOS). أي أصل آخر يُرفض.
3. **معرّف التطبيق** `sa.refers.jamiyati` في `apps/mobile/capacitor.config.ts` — **غيّره قبل أول نشر** إن أردت معرّفاً آخر؛ لا يمكن تغييره بعد النشر في المتاجر.

## الدخول بحساب Google في التطبيقين (مرة واحدة)
في مشروع Google Cloud نفسه الذي فيه معرّف الويب (`GOOGLE_CLIENT_ID`):
1. **أندرويد**: Credentials ← Create OAuth client ID ← **Android**: اسم الحزمة `sa.refers.jamiyati` وبصمة SHA-1 لمفتاح التوقيع. أضف بصمة كل مفتاح تُثبَّت به نسخة: مفتاح التصحيح (`cd apps/mobile/android && ./gradlew signingReport`)، ومفتاح الرفع، ومفتاح Play App Signing من Play Console ← App integrity. لا يوضع هذا المعرّف في أي ملف: التطبيق يستخدم معرّف **الويب**، والمعرّف الأندرويدي يثبت لـ Google أن التطبيق مسموح.
2. **iOS**: Create OAuth client ID ← **iOS** بمعرّف الحزمة `sa.refers.jamiyati`. ضع المعرّف في متغير الخادم `GOOGLE_IOS_CLIENT_ID` (الخادم يقبله جمهوراً ثانياً للرمز، والتطبيق يقرؤه من `/config/public`). ثم أضف في `apps/mobile/ios/App/App/Info.plist` نوع رابط (URL Type) قيمته **Reversed client ID** المعروض في صفحة المعرّف (يبدأ بـ `com.googleusercontent.apps.`):
   ```xml
   <key>CFBundleURLTypes</key>
   <array><dict><key>CFBundleURLSchemes</key><array><string>com.googleusercontent.apps.XXXX</string></array></dict></array>
   ```
3. إذا كانت شاشة الموافقة في وضع Testing فأضف حسابات المختبرين في Test users.
4. التغييرات في Google Cloud قد تأخذ ساعات قليلة لتسري. خطأ `[28444] Developer console is not set up correctly` في أندرويد يعني أن البصمة أو اسم الحزمة لا يطابقان.

## البناء التلقائي على GitHub (موصى به)
ملف `.github/workflows/mobile.yml` يعمل عند وسم إصدار (`v0.8.0`) أو يدوياً من تبويب Actions:
- **أندرويد**: ملف **APK** للتثبيت المباشر على أي جوال أو تابلت، وملف **AAB** لمتجر Google Play. يُوقَّع إصدار المتجر إذا أضفت الأسرار:
  `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
  إنشاء مفتاح الرفع (مرة واحدة، واحفظه في مكان آمن):
  `keytool -genkeypair -v -keystore upload.jks -alias jamiyati -keyalg RSA -keysize 2048 -validity 10000` ثم `base64 -w0 upload.jks`.
- **iOS / iPadOS**: بناء للمحاكي يثبت أن المشروع يُترجم. ملف **.ipa** موقّع يتطلب حساب Apple Developer (99 دولاراً سنوياً) وشهادة توزيع وملف Provisioning، ثم الرفع إلى TestFlight.
- رقم الإصدار يزيد تلقائياً مع كل بناء (`versionCode` = رقم التشغيل).

## البناء على جهازك
```bash
npm ci
cd apps/mobile
VITE_API_ORIGIN=https://app.example.sa npm run sync     # يبني الواجهة وينسخها للمشروعين
npx cap open android    # Android Studio ← Run على جوال أو تابلت أو محاكي
npx cap open ios        # Xcode (على Mac) ← اختر iPhone أو iPad ← Run
```
للتجربة مع خادم على نفس الكمبيوتر من محاكي أندرويد: `VITE_API_ORIGIN=http://10.0.2.2:3000`.

## قبل النشر في المتاجر
- **Google Play**: نموذج «سلامة البيانات» (رقم الجوال، الاسم، الصور التي يرفعها المستخدم)، وإقرار الميزات المالية: التطبيق **لا يقدم قروضاً ولا يحتفظ بالأموال**؛ تنظيم جمعيات ادخار بين أشخاص يعرفون بعضهم.
- **App Store**: وصف الاستخدام للكاميرا والصور موجود بالعربية والإنجليزية. يجب توفير **حذف الحساب** من داخل التطبيق قبل المراجعة (غير منفّذ بعد — مدرج في الخطوات التالية)، ورقم دخول تجريبي للمراجع.
- **التطبيقات المالية في السعودية**: المنصة تعمل بالنموذج A (تنظيم فقط، دون حيازة أموال). أي تغيير يجعلها تحصّل أو تصرف أموالاً يتطلب ترخيصاً (ADR-014).

## ما اختُبر وما لم يُختبر
- ✅ رحلة «التطبيق» في Chrome مع منصة Capacitor = android، على جوال (Pixel 7) وتابلت (حجم iPad أفقي): الدخول، التنقل، بقاء الجلسة بعد إعادة التشغيل، كل الطلبات تذهب للخادم فقط، رفض أصل غير مسموح، لا Service Worker، زر Google مخفي، لا تمرير أفقي (`scripts/test-native.sh`).
- ✅ `cap sync` ينسخ الواجهة و8 إضافات للمشروعين (منها إضافة الدخول بـ Google).
- ⏳ **الدخول بـ Google داخل التطبيقين لم يُجرَّب على جهاز حقيقي** في بيئة العمل هذه (لا محاكي أندرويد ولا Xcode). الخادم يقبل رمز iOS (اختبار آلي)، والواجهة تستدعي الإضافة حسب توثيقها؛ جرّبه على جهاز بعد إعداد Google Cloud أعلاه.
- ⏳ **لم يُبنَ ملف APK/IPA في بيئة العمل هذه**: شبكتها تمنع خوادم Google Maven وGradle. البناء الفعلي يتم عبر GitHub Actions أو Android Studio/Xcode على جهازك.
