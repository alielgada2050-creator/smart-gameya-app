# AGENT DECISION LOG

## ADR-001 — نموذج التشغيل A: أداة تنظيم فقط (معتمد من المالك 2026-11-09)

**القرار:** المنصة تنظم الجمعية (الأعضاء، الاتفاقيات، القرعة، الجدول، التذكير، السجلات) ولا تستلم أموال الأعضاء ولا تحتفظ بها ولا تحوّلها ولا تضمن السداد. كل عضو يحوّل مساهمته مباشرة إلى مستلم الدورة.

**النتائج التصميمية:**
1. لا يوجد تكامل مزود دفع في MVP؛ Phase 4 (Financial Engine) تُؤجَّل ويُعاد تعريفها كمطابقة إقرارات بين الأعضاء.
2. القسط يصبح "مدفوعاً" بموافقة طرفين: الدافع يُقرّ، والمستلم يؤكد (Maker–Checker طبيعي). للمستلم حق الاعتراض قبل التأكيد.
3. لا رسوم على المبالغ ولا عمولات تحصيل؛ الإيراد المستقبلي من اشتراكات الخطط فقط (PART 15).
4. لا غرامات تأخير؛ المسار: سماح ← متأخر ← تنبيهات ← سجل، دون تغيير الترتيب.
5. سياسة الرسوم حسب الدور (`fees.ts`) تبقى في النواة لكنها **غير مفعّلة** في الواجهة.
6. لا جمع لأرقام حسابات بنكية؛ مرجع التحويل نص حر قصير يختاره الدافع.
7. القرار قابل للمراجعة نحو النموذج B بعد رأي قانوني، دون إعادة كتابة: جدول `payment_intents/payment_webhooks` والدفتر المزدوج جاهزان.

## ADR-002 — قاعدة البيانات بدون ORM في المرحلة الحالية
استُخدم `pg` مع SQL صريح بدلاً من Prisma: القيود المالية تُفرض بـ triggers وقيود SQL يجب أن تكون مرئية ومختبرة، وتنزيل محركات Prisma غير متاح في بيئة البناء. يُعاد التقييم عند نمو عدد الوحدات.

## ADR-003 — القرعة commit–reveal مع ختم البذرة
البذرة تُشفّر بـ AES-256-GCM (`LOTTERY_SEED_KEY`) حتى التنفيذ، والالتزام يظهر للأعضاء فوراً. قاعدة البيانات ترفض أي بذرة لا تطابق الالتزام. في الإنتاج يُنقل المفتاح إلى KMS.

## ADR-004 — الذكاء الاصطناعي على مزودين مجانيين مع بديل ثابت (2026-11-09)
**القرار:** سلسلة Groq ← Cloudflare Workers AI ← قالب عربي ثابت، عبر واجهة OpenAI-compatible موحدة (`packages/ai-core`).
**المبرر:** صفر تكلفة في الإطلاق، لا ارتباط بمزود واحد (PART 4)، ولا توقف للخدمة عند نفاد الحصة.
**القيود:** النموذج يشرح فقط؛ الأرقام من `financial-core/savings.ts`؛ حارس أرقام إلزامي؛ حالة NOT_ADVISED لا تُرسل لنموذج؛ لا تخزين للنصوص. التفاصيل: `docs/AI_PROVIDERS.md`.
**مراجعة لاحقة:** الانتقال لطبقة مدفوعة أو نموذج مستضاف داخل المملكة عند تجاوز الحصص أو إذا اشترط تقييم PDPL ذلك.

## ADR-005 — تدوير رموز التجديد مع كشف إعادة الاستخدام
رمز وصول JWT لمدة 15 دقيقة + رمز تجديد معتم لمدة 30 يوماً يُخزَّن كبصمة فقط. كل رمز يُستخدم مرة واحدة؛ تقديم رمز سبق تدويره يلغي كل جلسات العائلة.

## ADR-006 — أول واجهة للمستخدم: تطبيق ويب قابل للتثبيت (PWA) قبل Flutter (2026-11-09)
**السياق:** البرومت يحدد Flutter للتطبيقات، لكن مضيف تنزيل Flutter SDK محجوب في بيئة البناء، بينما npm ومتصفح Chrome متاحان.
**القرار:** `apps/web` بـ React + Vite + TypeScript، عربي RTL أولاً مع الإنجليزية، فاتح/داكن، قابل للتثبيت على الجوال، يُخدَم من نفس أصل الواجهة البرمجية مع CSP صارمة.
**الضوابط:** الواجهة لا تحسب أي مبلغ أو تاريخ (معاينة الجمعية من `POST /gamiyas/preview`)؛ رمز الوصول في الذاكرة فقط، ورمز التجديد في localStorage مع تدوير وكشف إعادة استخدام.
**Flutter لاحقاً:** يُبنى على جهاز المطور فوق نفس عقد الواجهة البرمجية (`docs/API_DOCUMENTATION.md`) دون تغيير الخادم.
